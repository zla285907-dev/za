# تكامل Electron — نظام الحسابات والإدارة المالية للمزرعة

## الحالة الحالية

- **المتصفح (المعاينة):** يعمل التطبيق بقاعدة بيانات PGlite محفوظة في IndexedDB.
- **سطح المكتب (Electron):** العملية الرئيسية تفتح قاعدة بيانات SQLite عبر better-sqlite3، والواجهة تتصل بها عبر جسر IPC آمن (`preload.js`).

## التشغيل والاختبار

```bash
npm install                 # من جذر المشروع (واجهة الويب)
cd electron && npm install  # تبعيات سطح المكتب
npm test                    # داخل electron/: اختبارات قاعدة البيانات والمحاسبة والصلاحيات
```

آخر تشغيل: 168 اختبارًا ناجحًا من 168 في `electron/` (قاعدة SQLite حقيقية)، و50 من 50 في جذر المشروع (منطق مالي بدون قاعدة بيانات). التحقق من النوع والبناء الإنتاجي ناجح.

## ما تم التحقق منه

- **تكلفة المخزون في المشتريات:** خصم الفاتورة يُوزَّع على الأصناف، فتتطابق قيمة المخزون مع حساب المخزون في الأستاذ العام (مثال: 2 × 8000 بخصم 2000 = 14000).
- **المرتجعات:** مرتجعات المبيعات والمشتريات تُسعَّر بالصافي بعد الخصم، ولا تتجاوز الكمية المتبقية في الفاتورة.
- **حماية الحذف:** لا يُحذف الطرف المرتبط بشيك أو تحويل مالي.
- **النسخ الاحتياطي (سطح المكتب):** إنشاء النسخة في مجلد `Backups`، وقائمة النسخ، واستعادة نسخة محددة من القائمة فقط (لا يُقبل ملف خارجي). الاستعادة تنشئ نسخة أمان أولًا وتتحقق من سلامة الملف قبل الاستبدال، ثم يُعاد تشغيل التطبيق.
- **النسخ الاحتياطي (المتصفح):** التصدير إلى ملف JSON، والاستعادة تستبدل جداول النسخة داخل معاملة واحدة. تم اختبار دورة التصدير والاستعادة فعليًا على PGlite.

## الفروقات بين سطح المكتب والمتصفح

- سطح المكتب يخزن البيانات في SQLite عبر IPC، والمتصفح في PGlite داخل IndexedDB.
- النسخ على سطح المكتب تُحفظ في مجلد التطبيق (لا تُنزَّل)، والمتصفح ينزّل ملف JSON.
- استعادة سطح المكتب لا تقبل ملفًا من خارج التطبيق؛ يجب اختيار نسخة من قائمة النسخ.

## استيراد CSV على سطح المكتب

الاستيراد يبدأ بالمعاينة ثم التأكيد. المعاينة لا تكتب شيئًا، والتأكيد يحفظ كل الصفوف في معاملة واحدة أو لا يحفظ شيئًا.

- الملف بترميز UTF-8 وفاصلة بين الأعمدة، والحقول التي تحتوي فاصلة توضع بين علامتي اقتباس.
- الصف الأول قد يكون عناوين، وإن لم يوجد يُقرأ كبيانات.
- الحد الأقصى 2000 صف في الملف الواحد.
- إذا وُجد أي خطأ، لا يُستورد أي صف. المكرر يُتخطى ولا يُستبدل.
- المعاينة تُظهر الصفوف الجاهزة، والمكررة، والصفوف بها أخطاء مع رقم السطر.

### الأطراف (عملاء وموردون)

- الأعمدة بالترتيب: **الاسم** (مطلوب)، **النوع** (اختياري)، **الهاتف** (اختياري).
- النوع: `customer` أو `عميل` أو `مورد` أو `supplier`. إذا تُرك فارغًا يُعتبر عميلًا.
- الهاتف من 6 إلى 20 حرفًا، أرقام فقط مع السماح بـ + والمسافات والشرطات.
- التكرار: الاسم والنوع نفسهما موجودان في النظام أو في الملف.

### الأصناف

- الأعمدة بالترتيب: **الاسم** (مطلوب)، **التصنيف** (`feed` أو `supplies` أو `medication` أو `spare_parts` أو `other`، والافتراضي `supplies`)، **الوحدة** (الافتراضي "وحدة"، حتى 30 حرفًا)، **رمز الصنف** (اختياري وفريد)، **حد إعادة الطلب** (اختياري، حتى ثلاث خانات عشرية).
- التكرار: الاسم (بغض النظر عن حالة الأحرف) أو رمز الصنف موجودان في النظام أو في الملف.
- الصنف المستورد يُنشأ برصيد صفر. الرصيد الافتتاحي يُسجَّل بإذن استلام مخزون وليس عبر الاستيراد.

### الموظفون

- الأعمدة بالترتيب: **الاسم** (مطلوب، حتى 100 حرف)، **الهاتف**، **المسمى الوظيفي**، **نوع الأجر** (`monthly` أو `daily`، والافتراضي `monthly`)، **الأجر** (بالقروش، عدد صحيح)، **تاريخ التعيين** (بصيغة `YYYY-MM-DD`، اختياري).
- التكرار: الاسم (بغض النظر عن حالة الأحرف) موجود في النظام أو في الملف.
- الموظف المستورد يُنشأ بحالة "نشط". الأجر بالساعة غير مدعوم في الإنشاء وفق قواعد التطبيق.

## قيود معروفة

- **الاستعادة على سطح المكتب:** النسخة تُنسخ أولًا إلى ملف مؤقت بجانب قاعدة البيانات (`farm.db.restore-tmp`) وتُتحقق من سلامتها وهي مفتوحة. إذا فشل التحقق، تُحذف النسخة المؤقتة ولا تُغلق قاعدة البيانات الحالية. إذا فشلت الاستعادة بعد إغلاق القاعدة، يُعاد تشغيل التطبيق تلقائيًا ليفتح قاعدة البيانات الأصلية أو يُعاد الفتح بعد الاستبدال.
- **الطباعة وA4:** توجد قواعد طباعة (`@media print` وصفحة A4 بهامش 12 ملم) في `src/index.css` فقط. لم يتم اختبارها في معاينة طباعة فعلية، ولم يُتحقق من اتجاه العربية في المخرجات المطبوعة. زر PDF في صفحة التقارير يفتح نافذة الطباعة فقط ولا يُنشئ ملف PDF مباشرة.
- **استيراد Excel وPDF:** غير مدعومين. الاستيراد يقبل ملفات CSV فقط.
- **الاستيراد على المتصفح:** مسار الأصناف والموظفين القديم في المتصفح لا يتحقق من الصفوف ولا يعمل في معاملة واحدة، ولا تستخدمه لبيانات إنتاجية. على سطح المكتب يعمل المسار الكامل لكل الأنواع الثلاثة.
- **الشيكات على المتصفح:** مسار الشيكات في المتصفح (PGlite) لا يطبّق التحصيل أو الصرف أو الارتداد أو الإلغاء بعد الإصدار، وهو خارج نطاق النسخة المكتبية المعتمدة للإنتاج. الشيكات المعتمدة تُدار على سطح المكتب فقط.
- **النسخ الاحتياطي الإضافي:** استعادة النسخة تحتاج إعادة تشغيل التطبيق بعد النجاح.
- **قيود الشيكات (سطح المكتب):**
  - لا يُنشأ شيك إلا لطرف محدد (عميل أو مورد).
  - شيك وارد: يُقيَّد عند الاستلام (أوراق القبض)، ثم عند التحصيل يُصرف إلى الخزينة المختارة كسند قبض، وعند الارتداد أو الإلغاء يُعكس القيد.
  - شيك صادر: يُقيَّد عند الإصدار (أوراق الدفع)، ثم عند الصرف يُسجَّل سند صرف من الخزينة المختارة، وعند الإلغاء يُعكس القيد.
  - التحصيل والصرف يتطلبان خزينة نشطة. الانتقالات غير المسموحة تُرفض ولا تغيّر أي دفتر.
  - كل انتقال حالة يُرحَّل في قيد متوازن واحد، ومعرّف المرجع لكل مرحلة مختلف (`check_open` و`check_settle` و`check_reverse`).
- **تكرار الإرسال:** المصروفات والإيرادات والسلف والمرتجعات النقدية لا تملك حماية من الإرسال المكرر.
- **Windows:** لم يُنتج ملف التثبيت في Linux. أوامر البناء على Windows (من مجلد المشروع): `cd electron`، ثم `npm install`، ثم `npm run build:win`، والتحقق من ملف `.exe` في `electron/release/`.

## مسارات البيانات

- قاعدة البيانات: `%APPDATA%/<اسم التطبيق>/Database/farm.db`
- النسخ الاحتياطية: `%APPDATA%/<اسم التطبيق>/Backups/`

هذه المجلدات خارج مجلد التثبيت فلا تضيع البيانات عند التحديث.

## بناء ملف تثبيت Windows

من مجلد المشروع على جهاز Windows:

```bash
cd electron
npm install
npm run build:win
```

يبني هذا الأمر واجهة الويب أولًا ثم يحزم التطبيق. النتيجة المتوقعة هي ملف `.exe` (مُثبِّت NSIS) في `electron/release/`.

**حالة البناء الأخيرة:** لم يُشغَّل التحزيم في بيئة Linux لأن electron-builder يحتاج Wine لإتمام خطوة NSIS. يجب تشغيل الأوامر أعلاه على Windows والتحقق من ملف التثبيت الناتج قبل توزيعه.

## ملاحظات البناء

- ملف الأيقونة `public/icon.png` غير موجود حاليًا؛ تم إيقاف ربطه بالبناء.
- توقيع ملف `.exe` معطّل (`signAndEditExecutable: false`) لأن أدواته تحتاج Windows أو Wine.
- التطبيق يعمل دون إنترنت بعد التثبيت ولا يعتمد على أي خدمة سحابية.
